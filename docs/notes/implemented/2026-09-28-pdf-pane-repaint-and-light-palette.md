# Note: PDF 批注页：重绘只跟文档走，配色改读 shell 的真实别名

Status: implemented

## Problem

两个报告：PDF 批注页「刷屏厉害」；浅色模式没有优化。第一处有两个各自独立的成因，都在真实浏览器里量到了。

- **拖动一次宽度就整页重绘。** `PdfBody` 把 `paneWidth` 当作光栅化的入口，而且渲染前先 `setBitmap(null)`：宽度每变一点就先把这一页清空成「正在渲染这一页…」，再等一次完整光栅化。一次 44px 的拖动（本机探针，12 步）就是 12 次整页光栅化与 2~4 次白屏闪烁；侧栏拖动是逐像素的，于是拖动期间画面一直在刷。
- **壳每重渲染一次就重读一次侧车。** 侧车读取效果的依赖里放了 `seat` 与 `t`，而插槽的注入面每次构造都会新建座位（`inject` 里 `createDocumentSeat(...)`）、`LazyPdfBody` 里又新建一个副本座位：地址没变也会重新 GET 一次，并把阅读者还没保存的模式、总体说明与标注全部按磁盘状态重置。探针（每渲染重建一次注入面）里一次重渲染 = 一次 `GET /dsh-annotator/annotation`，两次重渲染 = 三次读取。当前 shell 会把一个条目的注入面按（条目、绑定）缓存（`ui-renderer` 的 `cachedSessionInject`），所以这是潜伏缺陷而不是现状：条目被替换、或壳改变缓存策略，它就会现形。规格现在把「同一份文档只读一次」钉住。
- **浅色模式没有优化是因为那些别名根本不存在。** 样式表读的 `--dsw-alias-text-l1/l2/l3`、`--dsw-alias-bg-l1/l2/l3`、`--dsw-alias-danger`、`--dsw-alias-success` 在 shell 的主题表里一个都没有（权威表是 `packages/client/ui-theme/src/styles/design-platform.css`，只有 `--dsw-alias-border-l1` 与 `--dsw-alias-brand-primary` 命中了）。于是文字一直吃暗色兜底 `#e6e6e6`：浅色模式下近白字压在近白底上，窄侧栏里连工具条文字都看不清。

## Decision

- **一页一张栅格按宽度台阶取。** `renderWidth = ceil(paneWidth / 64) * 64`，渲染效果的依赖只有 `[pdf, page, renderWidth]`：台阶内的宽度变化不再触发任何光栅化，台阶之间的变化也只为新的一档渲染一次。栅格本身按「这一档宽度」渲染、显示时再缩放到窗格实际宽度，所以代价只是台阶顶部最多 64px 的放大柔化。
- **页面不再先清空。** `shown` 把页码与栅格放在同一个状态里；同一页换宽度时旧图一直留在屏幕上，新的到了再换掉。（当时只有 `shown.page === page` 才算「有东西可显示」，翻页那一刻仍会退回提示——这一半已被 `2026-09-28-pdf-page-turn-commit.md` 取代：页号先变、栅格就绪再提交，翻页也不再清空。）
- **侧车的读取只以地址为输入。** `seat` 与 `t` 存进 ref、在调用点取最新值（重建后的注入面换了身份，但没换含义），效果依赖收成 `[address]`。翻到另一份文档仍然会读一次。
- **配色改读 shell 真实别名**（`label-primary/secondary/tertiary`、`bg-base`、`bg-layer-2`、`bg-document-preview`、`border-l1..l4`、`interactive-bg-hover`、`brand-primary`、`state-error/success-primary`、`label-error`），兜底值是 `inherit` / `transparent`——缺 token 时用宿主自己的颜色，而不是自带一套暗色。边框按 shell 的中性描边约定改 0.5px，圆角读 `--dsw-radius-sm`，全圆的色板补 `corner-shape: round`（否则被主题的超椭圆平滑削成异形）。
- **同批必须一起修的两处布局。** `.da-pdf` 变成真正的列（工具栏 + 正文），否则正文高度是「100% + 工具栏」、比窗格高 37px（窄窗格里会被裁掉一截滚动区）；工具栏早声明了 `flex-wrap:nowrap; overflow-x:auto`，但按钮默认可压缩、文字会折行，窄侧栏里被挤成竖排文字——补 `flex:0 0 auto` 与 `white-space:nowrap`，让它回到「一行、横向滚动」。

## Alternatives considered

- **「宽度变化超过阈值才渲染」**（效果里与上次渲染宽度比较）—— 要一个记住上次宽度的 ref，把可变状态塞进渲染路径；台阶法里「这张图对应哪一档宽度」是 `paneWidth` 的纯函数，测试可以直接钉住。
- **拖动时先渲染低分辨率、停下再补一次**（两级渲染 + 去抖）—— 收益是拖动过程中更清晰，但要引入分辨率状态与一次「停下」的判定，与这次要除掉的闪烁不是同一件事，留待有明确诉求时再做。
- **把座位做成 `useMemo` 或模块级单例** —— 注入面由 shell 构造，插件 memo 不了别人的调用；把协作者移出依赖（读 ref）是插件边界内能做到的等价保证。
- **插件自带一套浅色兜底**（`prefers-color-scheme` 或自己写 `--dsh-annotator-*` 再切换）—— shell 的主题是文档上的属性而不是系统偏好，「没有 token 时猜一套浅色」会在深色宿主上猜错；自己定义主题别名等于在插件里再造一个主题，违反「feature 包只消费语义别名」的约定。用继承值把决定权交回宿主。
- **翻页时也保留上一页的图**（不显示「正在渲染这一页…」）—— 旧页的图冒充新页比一次提示更糟；翻页的提示是诚实的反馈，只是每次翻页一次。（**已被 `2026-09-28-pdf-page-turn-commit.md` 取代**：量到「提示」的代价是整块面板塌陷、94% 像素变两次、一帧空白，且每次翻页都发生；新做法是先改页码、栅格就绪再提交，冒充本身不再可能。）

## Consequences

- 拖动侧栏：一次 44px 拖动从 12 次整页光栅化降到 1 次，白屏闪烁从 2~4 次降到 0（本机探针复测）；代价是栅格最宽比窗格宽不超过 63px 的像素，以及台阶顶部最多 64px 的柔化。
- 同一份文档只读一次侧车（探针：重建注入面 5 次 = 0 次宿主请求），未保存的模式、说明与标注不再被一次重渲染重置；规格 `the shell around the document` 用「引入回归 → 变红 → 回退」验证过（把依赖改回 `[address, seat, t]` 时那条断言变红，说明、标注两条也变红）。
- 深浅两套配色都由 shell 的别名决定：浅色下文字是 `rgb(15,17,21)`、画布是 `rgb(235,238,242)`，深色下是 `rgb(249,250,251)` 与 `rgb(21,21,23)`（探针实测）；窄侧栏（294px 窗格）的工具条是一行 36px、横向滚动，不再是竖排文字。
- 翻页仍会显示一次「正在渲染这一页…」；连续滚动与 PDF 文本层仍未做（见 `2026-09-28-pdf-annotated-as-one-document.md` 的已知取舍）。（**已被 `2026-09-28-pdf-page-turn-commit.md` 取代**：提示现在只在首次打开出现一次。）
