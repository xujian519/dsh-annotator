# Note: Markdown 的编辑与差异（取代 md 标注）

Status: implemented

> 已落地 **期一**（2026-09-28）：md 预览实现、源文本编辑、行级差异、差异送进会话，全程**不落盘**。落地时的三个决定都由用户拍定：**只送会话不改盘**、**接管 md 默认预览**、**期一用零依赖 `<textarea>`**。期二（CodeMirror 高亮、逐行加注）、期三（写回原文件）未做。

## Problem

上一条 note（[2026-09-28-office-and-text-annotation.md](./2026-09-28-office-and-text-annotation.md)）给 md 设计的方案是"按源行区间标注"——用户选行、写一句说明、插件把"L12–L14：应改成 X"送进会话。这条路径的隐含前提是**用户只想说、不想改**。

但 md 与图片/PDF 有个本质差别：**md 的源文件就是智能体要改的那个东西，用户完全可以自己改**。对这类文本，画标记再让智能体"照标记去改"多绕了一圈：用户已经知道要改成什么，直接改出来，把 diff 交给智能体（让它落地到别处、或复核）更精确、也更省事。

所以把 md 的方案换成：**在文档预览里编辑 md → 与原文件对比 → 差异送进会话**。

同时要认清本机已有的能力，避免重复造：

- `dsh-better-sidebar` 的 `markdown` 视图**就是一个 CodeMirror 编辑器**：`md/markdown` 后缀、预览/编辑切换、脏点、`Ctrl/Cmd+S` 保存（`api.fsWrite` → 宿主 `fs.write`），还能把选中的行插进会话草稿（证据 A、B）。
- 它**已有 diff 视图**，但那是 **git 语义**：`git.diff` / `git.commit-diff` → `DiffView` 解析 unified diff（证据 C）。也就是说它对比的是 **HEAD**，不是"你打开文件时的那一版"，而"编辑前的那一版"恰恰是这个需求要的东西。

于是真正缺的是两件、也只该做这两件：**① 以"打开时的那一版"为基线的差异；② 把这份差异送进会话**（顺带把入口放进本插件的文档预览链路，而不是另一个人工流程）。

## Decision

md 不进"标注"家族，改走"编辑 + 差异"家族；Office 那半条 note 不受影响（仍为 proposed）。

### 1）编辑面

- 注册 `md/markdown` 的 `documentPreviews` 实现（`priority: 'extension'`、`loading: 'text-pages'`），正文按行渲染源文本并允许编辑；基线 = **正文加载到的原文**（`content.kind === 'text'` 的累积文本，`eof` 之前的编辑允许但状态栏标注"尚未读完"）。
- 期一编辑器用原生 `<textarea>` + 行号槽 + 统一的换行/Tab 处理：零新依赖，覆盖率门禁好过。期二若需要语法高亮，再把 CodeMirror 6 收进懒加载分块（`client.edit.js`），按 §2.9 把许可证写进分块 banner、按 §4 补构建门禁的负控制。
- 代价要认：接管 `md/markdown` 的默认预览后，**读 md 时看不到渲染结果**（内置的渲染预览仍能从查看器下拉切回，证据 D）。要么接受这一次点击，要么不接管 md（那样就只能在 better-sidebar 的编辑器标签页里改，本插件不新增 md 预览）。

### 2）差异

- 基线是**打开时的那一版**，不是 git 的 HEAD：`figure.sha256`（既有 GET 已返回）标记基线版本，编辑中的文本与它做**行级 LCS**，输出 unified diff（`--- a/<名> +++ b/<名> @@ … @@`）与统计（`+N −M`）。
- 差异算法与渲染都是本插件自己的纯函数（无依赖）：算 diff 一个模块、渲染 diff 一个组件，各自 100% 覆盖。
- 文件在编辑期间被外部改动时（重新 GET 比对 `sha256`）按既有 `stale` 方式告警，不静默覆盖。

### 3）两个出口，必须分成两个动作

- **「送至会话」**（推荐默认）：**不写盘**。消息里带 unified diff、基线 `sha256`、统计与逐条纪律；可选把编辑结果作为附件 `<名>.edited.md` 随消息发送（走既有 `fileUpload`）。这样 AGENTS.md §2.2「唯一的写入面是两个侧车文件／标注绝不修改被标注的文档」**原样成立**。
- **「写回原文件」**（显式第二动作，需你批准）：真的改 md。这是本插件第一次修改被标注的文档 → §2.2 与 README「不做图面编辑」都要改写，并按 §8「改 Host/Client 契约」单独拍板。文本类文档没有"派生副本"可写（`<名>.md.annotated.md` 只是快照、不是源），所以要么写回原文件、要么不写——不建议发明第三种"半写"语义。

### 4）送进会话的消息

- 新增一个与 `buildAnnotationMessage`（[session.ts:107](../../../src/client/session.ts#L107)）并列的 `buildEditMessage`：前缀换成「【文档修改建议】」、正文是 fenced 的 unified diff + 统计 + 处理纪律（"改动以 diff 为准，按它落地到源文件；diff 之外的部分不要动"）。
- `guidance.ts` 增加对应段落（第二段静态提示）：说明这类消息的 shape、diff 的读法、以及"用户已经改好了，你的活是落地与复核"。
- 投递仍走 `sessions.prompt(content, 'queue')`，与标注同一条通道，不新增旁路。

## Alternatives considered

- **继续做 md 的按行标注**（上一条 note 的方案）：落选为**主路径**。它要求用户先描述再让智能体改，而 md 的改动用户自己就能精确表达；改留作 diff 之外的补充（在 diff 上给某行加一句"为什么"）会更自然，但不是期一范围。
- **复用 better-sidebar 的编辑器（注册它的 `FileViewerDescriptor`，或从预览里 hand-off 到它的标签页）**：落选为**主路径**。它保存即写盘（不可作为"仅建议"），diff 是 git 语义而非"打开时那一版"；而且这条链路只在装了该插件时存在（不满足 §2.6 的硬依赖纪律）。可作为期二的一个"若在则显示『在侧栏编辑器中打开』"的可选增强。
- **只在 git 面板里看 diff，不送会话**：落选。git 基线是 HEAD，用户可能已经提交过中间状态；而且用户要的是"让智能体知道我刚改了什么"，不是"让 git 记录"。
- **写 `<名>.edited.md` 副本，diff 两个文件**：落选为默认，但保留为「写回原文件」之外的可选出口之一。理由：它会产出与源同目录的第二个"看起来也是真身"的文件，长期会让人分不清谁是源；而"仅送会话"已经能把 diff 带进会话，不需要先在磁盘上制造一份。
- **把 md 编辑做成第三个侧车 JSON（记录 diff）**：落选。diff 是派生结果，随时可从"基线 + 当前文本"重算；落盘只会多一份要同步的状态。

## Consequences

换来的：md 走通了"改 → 看得见改了什么 → 送进会话"这条最贴合文本源的路；代价是插件第一次需要**编辑**能力，而它的自我定位原本是"只采集，不改文档"。

要认的账：

1. **定位变化**：README 的「不做图面编辑：插件只采集标注，不改图」在 md 上不再成立（文本源没有"生成源"可改，用户就是源作者）。若批准"写回原文件"，§2.2 必须改写并配套一条"写入面"规则：写目标仍由地址派生（不接受调用方给路径），且必须经一次显式确认。
2. **默认预览的取舍**：接管 md = 读 md 失去渲染视图（可切回）；不接管 = 本插件不新增 md 预览。这是 UX 决定，见待决 2。
3. **覆盖率**：diff 算法、diff 渲染、编辑状态机（dirty / stale / eof 未到）、写回失败路径都要进 100% per-file 门禁；没有豁免。
4. **编辑器的分块纪律**：期二上 CodeMirror 时，它必须只住在分块里、经 `require.async` 加载、许可证进 banner，并补上 §4 的构建负控制。
5. **基线语义要写进文档**：`sha256` 是"打开时那一版"的身份；它与 git 的 HEAD 不是一回事，README 里要说清，否则用户会以为 diff 是 git diff。

## 期二：零依赖那半（已落地）

三件事，都在同一条"不落盘"的链路上：

1. **每处改动一条说明**。说明挂在 **hunk** 上，键是它的基线侧起始行（`oldStart`）——基线是冻结的，所以读者继续改别处时说明不会漂。消息里 diff 块之后逐条列 `1. 第 6 行（@@ -3,7 +3,7 @@）：…`；**fenced diff 保持干净**，因此仍然可以直接 `patch`。读者后来把那处改动撤掉了，说明照样发（行号是他自己的引用），只是不带 hunk 头——不静默丢用户写下的东西。
2. **复制 diff**：整份 unified diff 进剪贴板（不是被消息预算裁过的那份）。剪贴板不可用/拒绝写入都进状态栏，不静默失败。
3. **光标位置读数**：工具栏常显 `第 N 行 · 第 M 列`（键、点击、编辑三条路径都会更新）。`select` 事件没进这条链：jsdom 里 React 的合成 `onSelect` 根本触发不了，而键、点击、编辑三条已经覆盖真实浏览器里所有移动光标的方式——宁可不写一条测不到的处理器。**行号槽只在关闭"自动换行"时出现**——软换行会让一行占多个视觉行，届时行号必然错位；所以换行开着时用行列读数代替，而不是给一个会漂的行号。换行开关仍是 shell 工具栏那个（本插件注册时声明了消费它），我们没有再造一个。

一处复盘：期一里 `busy` 初值写成 `false` 而按钮判 `busy !== null` 导致按钮锁死，**期二在复制按钮上又犯了同一个**（同一个布尔、同一个写法）。两次都是测试先抓到、不是真机——说明 §9.4 那条纪律（`disabled` 是提示、判定在处理器里）之外还要加一句：**同一个状态别在两处各写一遍条件**，写第二遍时就该抽成一个派生布尔。

## 已决（2026-09-28，由用户拍定）

1. **写盘策略**：只送会话，**不改盘**——§2.2 原样成立，插件没有新增写入面。
2. **接管 md 的默认预览**：接管（在文档预览里直接编辑；读 md 需从查看器下拉切回内置渲染预览）。
3. **期一编辑器**：零依赖 `<textarea>`（无新依赖、无新分块、许可证与构建门禁零增量）。
4. **期二先做零依赖那半**（复制 diff、每处说明、行列读数）；CodeMirror 语法高亮作为独立一步，动手前先定依赖（§8 ask first：新运行时依赖会进 Client 单文件包）。
