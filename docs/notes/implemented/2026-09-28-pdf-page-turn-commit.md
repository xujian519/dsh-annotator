# Note: PDF 翻页：一次提交，而不是先把整块面板清空

Status: implemented

## Problem

阅读者在标注态翻页时看到「屏幕闪烁」。用逐帧截图量它（本机 Chromium、真实 `lib/` 产物、真实主题表、窗格 840×824、devicePixelRatio 2；文档是 3 页「扫描件级」重页——每页 3400+ 个色块）：

- 一次翻页里 **77%~94% 的像素变了两次**，中间夹着**一帧近似空白**：该帧亮度标准差 8，而同一份文档有页时是 69~75（轻量文档 34~35）。也就是「整页 → 一行提示 → 整页」。
- DOM 侧同一条证据：栅格产出与窗格回到有页之间，整块只剩 `<p class="da-hint">正在渲染这一页…</p>`——`.da-root`（含标注工具条、页面、说明框、批注列表）与 `.da-stage` 一起消失（探针里这次窗口 26~42ms，因为它的栅格只要 8ms；真实扫描件的栅格化要数百毫秒，窗口随文档重量拉长）。
- 连续翻三次：两次塌陷窗口、一帧空白帧（`flatFrames: 1`、最低标准差 8）。

成因是两条规则叠在一起：`PdfBody` 只在 `shown.page === page` 时才有东西可显示，而翻页那一刻页号先变、栅格后到，于是文档工具栏之下的全部内容被一行提示替换；紧接着 `AnnotatorBody` 以 `key={page}` 重新挂载，新的 `<img>` 才开始解码。

图片半边没有这个现象：它没有页、也没有栅格化——读者「图片只有浅色模式问题、PDF 标注态才闪」的观察与这条对得上（标注态的静置、绘制、输入、滚动另行量过：0 次栅格化、0 次 DOM 变化、0 次布局位移）。

## Decision

- **页号与像素分成两个状态，一次渲染一起换。** `requested` 是读者要的页（工具栏数字、翻页按钮、栅格化请求都用它），`shown` 是屏幕上这一页（`{page, bitmap}`）；栅格就绪时才 `setShown({page: requested, …})`。在它之前窗格一直显示上一页，并且是**整页**的上一页——像素、覆盖层、说明框、批注列表都属于同一页，因为 `AnnotatorBody` 以 `shown.page` 为 key。
- **等不到第一张栅格时，占位只占页面区域。** `.da-placeholder` 与正文的 `.da-stage` 同为 `flex:1 1 auto` 的一列：工具栏、页码、保存按钮从第一帧起就在原位，页面到了它们不移动。
- **草稿按 `shown.page` 归档，而不是 `requested`。** 翻页待栅格的那一小段时间里读者画下的标注属于它画在的那张图；`reportDraft` 从 ref 读屏幕上的页，回调身份因此也永远不变。
- **未打开前不陈述文档自己的事实。** 工具栏现在从第一帧起就在屏幕上，所以页码在文档打开前只显示「1」、`共 N 页 · M 处批注` 到打开后才出现——等待态不该报出它还不知道的页数。（`pdf === null` 与真的「0 页」是两件事，后者仍显示 `1 / 0`。）
- 翻页提示从此只在**首次打开**出现一次。

## Alternatives considered

- **沿用 `2026-09-28-pdf-pane-repaint-and-light-palette.md` 的「翻页先显示提示」** —— 那条的取舍是「旧页冒充新页比一次提示更糟」。这批量到提示的代价：整块面板塌陷、94% 像素变两次、一帧空白，而且每次翻页都发生。改法让冒充风险本身消失——覆盖层与草稿始终只对屏幕上的那一页，工具栏数字领先的是**没有像素**的那一小段时间，而不是错的像素。
- **翻页时保留旧页的像素、但把覆盖层换成新页的** —— 允许标注落在错误坐标上（读者可能按旧页的图在新页的覆盖层上点下去），还要引入第二套「这一层属于哪一页」的判断。
- **等 `shown` 提交后再改工具栏数字（整块一起滞后）** —— 点击后没有任何反馈，快速连点两页会像丢页；数字先到、页面随后正是阅读器该有的手感。
- **翻页时先画一张低分辨率快图** —— 消除不了塌陷（塌陷来自「没有可显示的东西」），只是把空白期缩短一点，还多一套栅格状态。

## Consequences

- 翻页不再有空白帧：同一支探针复测，翻一页与连续翻三页都是 `flatFrames: 0`、最低标准差 69（基线 75；修复前最低 8），提示窗口 0 次、`<img>` 空白帧 0 次；DOM 轨迹只剩一次 `img` 变化，不再出现 `surface: null`。
- 窄侧栏（384px 窗格）标注态复测：翻页 0 次布局位移、1 次栅格化；静置 5 秒 0 次栅格化、0 次 DOM 变化、0 次布局位移。
- 首次打开仍有一次占位（除第一次栅格化外无可显示的东西），但工具栏与窗格框架不移动：探针抓到的等待帧是「工具栏齐全 + 灰色页面区 + 正在渲染这一页…」。
- 页码可能领先屏幕上的页一个栅格的时间（本机探针里 8ms，真实扫描件可达数百毫秒）：工具栏数字是读者的请求，`documentScope` 的批注数仍按整份文档统计。
- `AnnotatorBody` 仍以 `key={shown.page}` 重新挂载，所以每页的撤销历史、工具与缩放选择仍是各页各一份；`mode` 与 `summary` 由文档层持有，翻页不重置。
- 端到端验收（`/tmp/annotator-browser-check`，22 项）全过；其中「下一页没有自己的标注」这一条原本在点完按钮、只等页码变化后就断言，正是这次改掉的时序——它改成等栅格落地（`turnTo`：页码到位 + `img.src` 换掉且解码完成），断言从 22 项里的 1 项失败变成全过，且「回到第一页仍显示第一页的标注」改成断言标注文本而不是标注条数。
